# Riko hub: shared brain, memory and personas

Status: contract for the "hub" round. Children follow this literally. If something here
is wrong or missing, say so in your final report — do not edit this file.

## Why

Today the desktop app keeps everything on one PC: the system prompt and avatar
(`character_config.yaml`), the chat (`chat_history.json`) and the LLM calls (`riko/llm.py`).
The **hub** moves those into one small server so that any client (desktop app, terminal,
a future Android app, the web config page) reads the same state and carries on from where
the last one stopped, and so personas can be switched by keyword while she is running.

```
            ┌──────────── riko-hub (FastAPI, :8002) ────────────┐
desktop ───►│ /api/chat   personas   chat history   LLM settings│──► LLM (/v1/chat/completions)
android ───►│ SQLite + avatars in /data       web config page /  │
browser ───►└────────────────────────────────────────────────────┘
desktop ──── WAV clips ───► riko-asr (:8001, unchanged)
```

Two ways to run it, same code path for the clients (they always talk HTTP to a hub):

| mode | hub runs | config (`character_config.yaml`) |
|---|---|---|
| `local` (default) | inside desktop.py / main.py, on `127.0.0.1:<local_port>`, data in `hub_data/` | `hub.mode: local` |
| `remote` | Docker on the AI box (`~/AI/Docker/riko-hub`, port 8002) | `hub.mode: remote`, `hub.url` |

ASR stays a separate service (`server/`, unchanged except docs). TTS stays in the client.

## Hub package layout (owned by task A)

```
hub/
  __init__.py
  server.py      create_app(data_dir, api_key=None, llm_defaults=None) -> FastAPI ; main()
  store.py       SQLite store (personas, messages, settings, state)
  brain.py       LLM call: port of riko/llm.py logic (think-stripping, reasoning retry, model auto-pick)
  static/index.html   web config page (vanilla JS, no CDN, no build step)
  assets/default_avatar.vrm   copy of character_files/sample_avatar.vrm
  pyproject.toml uv.lock Dockerfile compose.yaml .env.example .dockerignore data/.gitkeep README.md
```

`hub.server.main()` reads env: `RIKO_HUB_KEY` (empty = no auth), `RIKO_HUB_HOST` (0.0.0.0),
`RIKO_HUB_PORT` (8002), `RIKO_HUB_DATA` (`/data` in Docker, `./data` otherwise), and LLM
defaults `RIKO_LLM_BASE_URL`, `RIKO_LLM_API_KEY`, `RIKO_LLM_MODEL` (default `auto`).

`create_app(data_dir: Path, api_key: str | None = None, llm_defaults: dict | None = None)` is
what local mode calls in-process. `llm_defaults` has the same keys as the `llm` settings
object below (`api_key` included). Defaults fill any field not saved in the store; values
saved via `PUT /api/settings` win over defaults.

First start on an empty data dir seeds one persona: id `riko`, name `Riko`, keywords
`["riko"]`, the current system prompt from `character_config.yaml` (snarky anime girl, calls
the user "senpai", 1-3 sentences, no markdown/emoji), greeting `"Riko here. Miss me, senpai?"`,
the default avatar, and makes it active.

## HTTP API (v1)

Auth: every `/api/*` route except `GET /api/health` needs `Authorization: Bearer <RIKO_HUB_KEY>`
when a key is configured; wrong/missing → `401 {"detail": "invalid api key"}`. Compare with
`hmac.compare_digest`. JSON everywhere unless noted. Times are ISO-8601 UTC strings.
CORS: not enabled (the web page is served by the hub itself).

### Objects

**Persona**
```json
{"id": "riko", "name": "Riko", "keywords": ["riko"], "system_prompt": "...",
 "greeting": "Riko here. Miss me, senpai?", "tts_voice": "", "avatar_version": 1,
 "updated_at": "2026-11-03T18:00:00Z"}
```
- `id`: slug of the name (`[a-z0-9-]`, unique, immutable). `avatar_version`: integer that
  increments on every avatar upload (clients cache avatars by `id` + `avatar_version`).
- `tts_voice`: optional voice name a client may pass to its TTS (empty = client default).

**Message**
```json
{"id": 42, "persona": "riko", "role": "user", "content": "hi", "source": "desktop",
 "created_at": "2026-11-03T18:00:00Z"}
```
`id` is global and monotonically increasing. `role` is `user` or `assistant`.
`source` is a free-form client name (`desktop`, `terminal`, `android`, `web`, `import`).

**State**
```json
{"version": 17, "active": <Persona>, "personas": [{"id": "riko", "name": "Riko"}],
 "last_message_id": 42, "llm_model": "qwen4exp"}
```
`version` increments on ANY change: persona switch, persona create/edit/delete, avatar
upload, new message, history cleared, settings change. Clients poll `GET /api/state` every
few seconds and react when `version` (or `active.id` / `active.avatar_version`) changes.

### Routes

| method & path | body | response |
|---|---|---|
| `GET /api/health` | – | `{"ok": true, "version": "1"}` (no auth) |
| `GET /api/state` | – | State |
| `GET /api/personas` | – | `[Persona]` |
| `POST /api/personas` | `{name, system_prompt, keywords?, greeting?, tts_voice?}` | `201` Persona; `409` if the slug exists; `422` if name empty |
| `GET /api/personas/{id}` | – | Persona / `404` |
| `PUT /api/personas/{id}` | any of `{name, system_prompt, keywords, greeting, tts_voice}` | Persona (id never changes) |
| `DELETE /api/personas/{id}` | – | `204`; `409` if it is the last persona. Deletes its messages and avatar. Deleting the active one activates the first remaining persona. |
| `GET /api/personas/{id}/avatar` | – | `.vrm` bytes, `Content-Type: model/gltf-binary`, `ETag: "<id>-<avatar_version>"`; the default avatar if none uploaded |
| `PUT /api/personas/{id}/avatar` | multipart field `file` (a `.vrm`, max 200 MB, must start with glTF magic `glTF`) | Persona (avatar_version +1); `400` on bad file |
| `POST /api/active` | `{"persona": "<id, name or keyword>"}` (case-insensitive) | State; `404` if nothing matches |
| `GET /api/history` | query `persona` (default active), `after` (message id, default 0), `limit` (default 50, max 500) | `{"persona": id, "messages": [Message]}` oldest→newest. With `after=0` it returns the LAST `limit` messages. |
| `DELETE /api/history` | query `persona` (default active) | `204` |
| `POST /api/history/import` | `{"persona": id, "messages": [{"role", "content"}], "replace": false}` | `{"imported": n}` (source `import`; used once to migrate `chat_history.json`) |
| `POST /api/chat` | `{"text": "...", "source": "desktop", "persona": optional id}` | ChatResult (below) |
| `GET /api/settings` | – | `{"llm": {base_url, model, temperature, max_tokens, max_history, reasoning_effort, extra_body, api_key_set: bool}, "switch_phrases": [...]}` — never returns the LLM key |
| `PUT /api/settings` | partial of the same; `llm.api_key` is write-only (`""` clears it) | same as GET |
| `GET /` | – | the web config page (static, no auth; it asks for the key and keeps it in `localStorage`) |

**ChatResult**
```json
{"reply": "Melon bread, obviously, senpai.", "persona": "riko", "switched": false,
 "message_ids": [41, 42], "state_version": 17}
```

### Persona switching by keyword (in `POST /api/chat`)

Before calling the LLM, normalise the text (lower-case, trim, strip trailing `.!?,`).
It is a **switch command** when either:
1. it equals one of a persona's `keywords`, its `name`, or its `id` exactly; or
2. it matches `^(<switch_phrase>)\s+(.+)$` and group 2 equals a persona's keyword/name/id.
   Default `switch_phrases`: `["switch to", "change to", "become", "persona", "talk to", "i want to talk to"]`
   (editable in settings).

On a switch: make that persona active, `reply` = its `greeting` (or `"<name> here."` when the
greeting is empty), `switched: true`, `persona` = the new id, nothing is stored in history,
`message_ids: []`. Switching to the already active persona also returns `switched: true`.

Otherwise: build `[system_prompt] + last max_history messages of that persona + user text`,
call the LLM, store the user message and the reply (both with `source`), return them.
LLM failure → `502 {"detail": "<reason>"}` and nothing stored. One chat at a time (lock);
concurrent requests queue.

### LLM settings defaults
`base_url` (required to chat; `503 {"detail": "LLM not configured"}` if empty),
`model: "auto"` (first id from `/v1/models`, re-resolved when settings change),
`temperature: 0.8`, `max_tokens: 4096`, `max_history: 40`, `reasoning_effort: ""`
(omit when empty), `extra_body: {}`. The reasoning-model retry behaviour from
`riko/llm.py::_complete` (retry once with doubled max_tokens, cap 16384, when the reply is
empty and `finish_reason == "length"`) must be kept.

## Client side (owned by task B)

`character_config.yaml` loses `history_file`, `system_prompt`, `vrm_model` (moved to the hub);
the `llm:` section stays only as the seed for local mode. New section:

```yaml
hub:
  mode: local                      # local = run the hub inside this app; remote = use hub.url
  url: http://192.0.2.51:8002    # remote only
  api_key_env: RIKO_HUB_KEY        # .env variable holding the hub key (both modes)
  local_port: 8002                 # local only; binds 127.0.0.1
  local_data: hub_data             # local only; relative to the project folder
```

`riko/hub_client.py` (new) wraps the API above (requests, timeouts, bearer key). In local
mode it first starts `hub.server.create_app(ROOT/local_data, key, llm_defaults_from_cfg)` with
uvicorn in a daemon thread and waits for `/api/health`. `riko/llm.py` is removed;
`riko/session.py`, `main.py`, `desktop.py` use the hub client. `riko-ctl persona <name>`,
a tray "Persona" submenu, and the avatar page reload the VRM on persona change (the local
viewer proxies `GET /avatar.vrm` to the hub's active avatar, cached on disk by id+version).
A state-poll thread (every 3 s) notices switches made from other clients.
`riko/migrate.py` (`uv run -m riko.migrate`) imports an old `chat_history.json` into the
active persona once and renames it to `chat_history.json.imported`.
